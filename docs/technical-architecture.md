# 工业软件跨平台 AI 插件技术架构文档（V2）

## 1. 架构目标

围绕“跨工业软件插件 + 企业级安全 + 3D→2D 刚需 + 渐进式智能化”设计技术体系，满足：
- 多软件接入的一致体验
- 任务级可靠交付（可追踪、可回退、可审计）
- 企业可部署（公有云/专有云/私有化）
- 从规则驱动平滑演进到 AI 驱动
- **支持 ReAct 闭环：先识别缺失信息，再执行动作补齐信息，再继续推理**

## 3. 关键新增：ReAct 闭环架构

### 3.1 闭环核心对象
- **Task Context**：任务目标、当前输入、历史动作、已获取证据。
- **Missing Info Graph**：缺失信息图谱（投影视图、结构树、尺寸链、公差、材料、BOM）。
- **Action Plan**：下一步动作计划（问用户/跑宏/检索）。
- **Observation**：动作执行结果（结构化返回 + 原始日志）。

### 3.2 闭环状态机
- `INIT`：接收任务，初始化上下文。
- `ANALYZE_GAP`：识别信息缺口与优先级。
- `PLAN_ACTION`：选择最优动作与参数。
- `EXECUTE_ACTION`：执行动作（如 SW 宏）。
- `OBSERVE_UPDATE`：回写结果并评估是否补齐。
- `DONE`：满足产出条件，生成结果。
- `HUMAN_HANDOFF`：超过阈值/高风险时转人工。

### 3.3 循环终止条件
- 必需信息全部满足；
- 达到最大轮次（例如 5 轮）；
- 连续动作失败超过阈值；
- 用户主动中断并转人工。

## 4. 分层设计说明

### 4.1 客户端与插件层（重点：SolidWorks）
- 在 SW 插件中提供任务发起、宏执行确认、结果回显。
- 提供“AI 请求动作面板”：显示缺什么信息、准备执行什么动作。
- 支持用户确认后执行宏，或人工修改宏后再执行。

### 4.2 接入与网关层
- API Gateway 统一鉴权、流控、审计注入。
- 支持 SSO（OIDC/SAML）对接企业身份体系。
- 对关键 API 引入幂等键，保证任务重试安全。

### 4.3 任务编排与闭环控制层
- **Task Service**：管理任务生命周期（创建、排队、执行、归档）。
- **Workflow Engine**：驱动大流程（出图、审核、修正）。
- **ReAct Loop Controller**：驱动小循环（识别缺失→动作→观察→再推理）。
- **State Store**：持久化每轮上下文与动作轨迹。

### 4.4 推理与决策层
- **Planner**：从任务上下文识别缺失信息。
- **Policy**：决定先问用户、先执行宏还是先检索。
- **LLM Gateway**：统一多模型路由与降级。
- **Prompt 模板中心**：按任务类型版本化管理。

### 4.5 动作执行层
- **Ask User Adapter**：结构化发问并接收用户补充。
- **SW Macro Runner**：
  - 生成宏代码（VBA/C# macro）；
  - 沙箱执行（限权、超时、资源隔离）；
  - 返回结构化结果（尺寸、特征树、视图信息等）。
- **Retrieval Adapter**：在标准/历史数据中检索证据。

### 4.6 数据与知识层
- 关系型数据库：租户、项目、任务、循环状态、审计元数据。
- 对象存储：3D 文件、2D 图纸、中间产物、宏执行日志。
- 检索系统：向量检索 + 关键字检索混合召回。
- 宏模板库：可复用宏（取尺寸、取特征、取属性、导出视图）。
- 规则库：行业标准与企业规则。

### 4.7 治理与安全层
- 可观测性：任务级 Trace + 循环轮次指标。
- 安全：KMS 管理密钥，静态与传输加密。
- 发布：蓝绿/灰度发布，支持租户白名单。
- 成本：按租户/模型/动作类型计量。

## 5. 核心业务流程（ReAct + SW 宏）

```text
[插件发起任务]
   -> [Loop Controller: 分析是否缺失关键信息]
      -> 若缺失: [Planner生成Action Plan]
         -> Action1: 询问用户(例如需要主视/剖视?)
         -> Action2: 生成并执行SW宏(提取结构树/尺寸链)
         -> Action3: 检索标准库(补充公差规则)
      -> [Observation回传并更新Task Context]
      -> [判断是否满足出图条件]
         -> 否: 进入下一轮循环
         -> 是: 生成2D图纸与审核报告
   -> [结果回写插件 + 人工确认]
```

关键设计点：
- 每轮都输出可解释信息：缺口、动作、结果、下一步。
- 宏执行失败可自动回退（重试、替代动作、人工接管）。

## 6. SolidWorks 宏执行子系统设计

### 6.1 宏生成
- 输入：任务目标 + 缺失信息类型 + 当前模型上下文。
- 输出：可执行宏代码（附动作说明与风险级别）。

### 6.2 宏执行安全
- 限制可调用 API 白名单。
- 限制文件系统和网络访问。
- 配置执行超时与资源上限。
- 全量记录宏源码、参数、执行日志、结果摘要。

### 6.3 宏结果标准化
统一返回结构：
- `feature_tree`（结构树）
- `views`（可用视图及方向）
- `dimensions`（关键尺寸链）
- `tolerance/material/bom`（工艺相关信息）
- `confidence`（提取置信度）

## 7. 多租户与安全架构

### 7.1 多租户隔离
- 逻辑隔离：Tenant ID 全链路透传 + 行级权限控制。
- 存储隔离：对象存储按租户命名空间隔离。
- 计算隔离：高安全客户可启用独立推理实例。

### 7.2 安全控制
- 传输：TLS1.2+；静态：AES-256。
- 审计：所有关键操作落审计日志（只增不可改）。
- 权限：RBAC + 项目级细粒度授权。
- 数据策略：默认不用于通用模型再训练（可配置策略）。

### 7.3 部署模式
- SaaS 多租户
- 专有云（VPC 单租户）
- 私有化（客户内网离线部署）

## 8. 关键技术选型建议（可替换）

- 插件侧：C++/C#（依据 CAD SDK），WebView + JS UI
- 宏体系：VBA/C# Macro + 受控执行宿主
- 网关：Kong / APISIX / Envoy
- 业务服务：Go 或 Java（强并发 + 稳定生态）
- 工作流：Temporal / Argo Workflows
- 状态机：Temporal State + Redis/PostgreSQL
- 规则引擎：Drools 或自研 DSL
- 数据库：PostgreSQL
- 检索：OpenSearch + 向量数据库（Milvus/pgvector）
- 对象存储：S3 兼容存储（MinIO/云厂商）
- 可观测性：Prometheus + Grafana + OpenTelemetry

## 9. 非功能性指标（SLO）

- 任务系统可用性：99.9%
- 核心 API p95 延迟：< 300ms（不含大文件上传）
- 3D→2D 标准任务完成时长 p95：< 10 分钟
- 宏动作执行成功率：≥95%（可重试后）
- 平均闭环轮次：≤3.5
- 审计日志完整率：100%
- 严重安全事件：0

## 10. 演进路线（架构维度）

### 阶段 A（MVP）
- SW 单平台插件 + 缺失信息识别 + 宏执行通道 V0
- 目标：验证“可循环补齐信息”的任务闭环

### 阶段 B（扩展）
- 多平台适配 + ReAct 策略引擎 + 检索增强
- 目标：提高闭环自动完成率和可复制性

### 阶段 C（平台化）
- 预测式策略学习 + 跨软件流程编排 + 成本治理闭环
- 目标：形成可复用的工业 AI 工作流平台
